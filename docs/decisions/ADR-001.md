# ADR-001: n8n workflow as the backend, not a local Python bot.

Status: accepted, 2026-10-08

Context: `SPEC_v3.md` section 2 planned `bot.py` on the Mac with Telegram long polling. The
owner said: build on n8n, which already runs at n8n.linkright.in. Decision: one n8n
workflow with a Telegram Trigger webhook. The order logic is pure JS in a Code node, built
from the repo by `n8n/assemble.js`. Trade-off: n8n quirks cost hours in live tests (IF
`singleValue`, the Config item shadowing the raw update, the `replyMarkup` literal). The
brain must stay free of n8n objects so tests run in plain node. Consequence: no Mac needs
to stay on. The bot runs where n8n runs. Webhook, not polling, so the spec's A4 assumption
is gone.
