# ADR-003: One MAIN workflow, no SUB workflows.

Status: accepted, 2026-10-08

Context: the house n8n rulebook says MAIN workflows own the trigger, Config and the kill
switch, and call SUB workflows when one workflow cannot do the job. The build ladder says:
one workflow if it can. Decision: one workflow, "Kuiklo MAIN 01 Telegram Order Bot", 21
nodes, in the Personal root (owner's call). Trade-off: the STT path, the LLM path, the FAQ
path and the voice path all sit on one canvas. Consequence: one deploy, one id
(`qAUgmP8Q7cvciLX9`), one place to read. Split into SUBs only if a second channel
(WhatsApp) or order writes make it too big.
